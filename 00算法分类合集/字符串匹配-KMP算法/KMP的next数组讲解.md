你已经能从视觉上判断 `next` 数组了，接下来要做的，就是把你脑中“找相同前后缀”的动作，翻译成代码。

我们先只写**构建 `next` 数组**的部分，不掺入字符串查找。代码里虽然会出现 `for` 和 `while`，但它们分别只负责一件事，我会拆开讲。

先统一约定：**本文的 `next[i]` 表示，从下标 `0` 到 `i` 的这段字符串中，最长相等的真前缀和真后缀的长度。** 有些教程的数组从 `-1` 开始，那是另一种写法，暂时不要混用。

例如：

```text
字符串： a b a b a
下标：   0 1 2 3 4
next：   0 0 1 2 3
```

对于最后一个位置：

```text
前缀： [a b a] b a
后缀：  a b [a b a]
```

相同部分是 `"aba"`，长度为 `3`，所以 `next[4] = 3`。

“真前缀、真后缀”表示不能把整个字符串本身算进去，否则答案永远等于字符串长度，就没有意义了。

---

**第一步：先把你视觉上会做的事情写出来**

假设我们已经处理好了：

```text
a b a b a
```

它的最长相等前后缀是：

```text
前缀： [a b a] b a
后缀：  a b [a b a]
```

长度是 `3`。

现在右边新来一个字母 `b`：

```text
a b a b a b
          ↑
        新字母
```

你大概会想：

> 原来的相同部分是 `"aba"`，如果接下来的字母也相同，是不是就能变成 `"abab"`？

对，代码就是利用这个想法。

把前缀后面的字母和新字母比较：

```text
下标：  0 1 2 3 4 5
字符：  a b a b a b
              ↑   ↑
         前缀下一位 新字母
```

两边都是 `b`，所以长度从 `3` 增加为 `4`。

**我们没有重新找一遍前后缀，而是接着上一次的结果向后延长。**

---

**第二步：用两个变量表示这两个位置**

我们给它们起名字：

```python
i  # 当前新加入的字符的下标
j  # 已经相等的前后缀长度，同时也是前缀下一位的下标
```

这里 `j` 有两个作用，刚开始比较容易绕，我们单独看：

```text
下标：  0 1 2 3 4 5
字符：  a b a b a b

已经匹配的前缀是：
        a b a
        └─3个─┘
```

既然已经匹配了 `3` 个字符，那么下一个要比较的字符就在下标 `3`：

```text
匹配长度 j = 3
下一位下标 = 3
```

因此：

```python
s[i]  # 新加入的字符
s[j]  # 前缀中等待与它比较的字符
```

如果它们相等：

```python
if s[i] == s[j]:
    j += 1
```

然后记录当前答案：

```python
next[i] = j
```

到这里，你已经理解了“匹配成功”时的全部代码。

---

**第三步：如果不相等，视觉上会发生什么？**

换一个例子，在 `"ababa"` 后面加的是 `c`：

```text
下标：  0 1 2 3 4 5
字符：  a b a b a c
```

新字符下标是：

```python
i = 5
```

前一段 `"ababa"` 的最长相等前后缀长度是 `3`：

```python
j = 3
```

先试着把 `"aba"` 延长：

```text
前缀这边希望得到：a b a b
末尾这边实际得到：a b a c
                       ×
```

也就是：

```python
s[j] == 'b'
s[i] == 'c'
```

不相等，说明长度为 `3` 的这条路延长不了。

但这时不能直接说答案是 `0`，因为**较短的相等前后缀，可能还有机会延长**。

我们看看刚才匹配的 `"aba"`：

```text
a b a
```

它自己还有相等前后缀 `"a"`：

```text
前缀： [a] b a
后缀：  a b [a]
```

所以，下一个值得尝试的匹配长度是 `1`。

原字符串中也确实保留着这个较短的对应关系：

```text
前缀： [a] b a b a
后缀：  a b a b [a]
```

现在只需要尝试，能不能把 `"a"` 延长。

---

**第四步：把“退到较短的相同部分”翻译成代码**

刚才已经匹配的部分长度是 `j`：

```text
s[0 : j]
```

它的最后一个下标是：

```text
j - 1
```

而这个部分自己的最长相等前后缀长度，我们以前已经算过，存在：

```python
next[j - 1]
```

因此，退到下一个候选长度的代码就是：

```python
j = next[j - 1]
```

把具体数字代进去：

```text
原来 j = 3
已经匹配的部分是 "aba"

"aba" 的最长相等前后缀长度：
next[2] = 1

所以：
j = next[3 - 1]
j = next[2]
j = 1
```

这行代码对应的视觉动作就是：

> **较长的相同部分接不上新字母，就缩到它内部较短的相同部分，再试一次。**

这里不使用 `j -= 1`，因为比当前长度小 `1` 的部分，不一定是相等的前后缀。

例如 `"aba"`：

```text
长度 2：前缀 "ab"，后缀 "ba"，不相等
长度 1：前缀 "a"， 后缀 "a"， 相等
```

`next[j - 1]` 可以直接找到已经确认相等的那个较短长度。

---

**第五步：为什么需要 `while`？**

因为缩短一次之后，仍然可能匹配不上。

继续刚才的例子：

```text
s = "ababac"
i = 5
新字母 s[i] = 'c'
```

整个尝试过程是：

| 当前 `j` | 已经相等的部分 | 等待比较的 `s[j]` | 与新字母 `c` 比较 |
|---:|---|---|---|
| 3 | `"aba"` | `b` | 不相等，退到 `next[2] = 1` |
| 1 | `"a"` | `b` | 不相等，退到 `next[0] = 0` |
| 0 | 没有 | `a` | 不相等，无法延长 |

所以我们需要反复执行：

```text
只要还有已匹配的部分，而且当前字符不匹配：
    就退到更短的候选长度
```

翻译成 Python：

```python
while j > 0 and s[i] != s[j]:
    j = next[j - 1]
```

注意这里的两个循环分别负责什么：

```text
外面的 for：
    换下一个新字符，也就是移动 i。

里面的 while：
    针对当前这个新字符，缩短候选匹配长度，也就是调整 j。
```

**`while` 运行时，`i` 不动，新字母一直是同一个。**

你可以在脑中把它读成：

```text
来了一个新字母。
先试长的。
接不上，就试短的。
还接不上，就再试更短的。
```

`j` 每退一次都会变小，最小退到 `0`，所以这个过程会结束。

---

**第六步：把三个动作拼起来**

针对每一个新字符，我们只做三件事：

```text
1. 接不上时，缩短候选长度。
2. 接得上时，匹配长度加 1。
3. 记录当前位置的答案。
```

对应代码：

```python
# 1. 接不上时，缩短候选长度
while j > 0 and s[i] != s[j]:
    j = next[j - 1]

# 2. 接得上时，匹配长度加 1
if s[i] == s[j]:
    j += 1

# 3. 记录答案
next[i] = j
```

为什么 `while` 后面还要有一个 `if`？

因为退出 `while` 有两种可能：

- 已经找到了能接上的位置。
- `j` 已经退到 `0`，还需要比较新字符与第一个字符。

因此，要用 `if` 再确认是否相等。相等才能加 `1`。

---

**第七步：完整代码**

代码中我用 `nxt` 作为数组名，因为 Python 已经有一个叫 `next` 的内置函数。`nxt` 就是我们讨论的 `next` 数组。

```python
def build_next(s):
    n = len(s)
    nxt = [0] * n

    # 当前已经相等的前后缀长度
    j = 0

    # 第一个字符的答案是 0，从第二个字符开始处理
    for i in range(1, n):

        # 接不上，就尝试较短的相等前后缀
        while j > 0 and s[i] != s[j]:
            j = nxt[j - 1]

        # 接得上，就将相等部分延长一个字符
        if s[i] == s[j]:
            j += 1

        # 保存以 i 结尾的这段字符串的答案
        nxt[i] = j

    return nxt
```

伪代码对照：

```text
函数 构建next数组(s)：
    创建与 s 等长的数组，初始值全部为 0
    j = 0

    从第二个字符开始，依次处理每个位置 i：

        当 j > 0，并且新字符与前缀下一位不相等：
            j = 已匹配部分内部的最长相等前后缀长度

        如果新字符与前缀下一位相等：
            j 加 1

        next[i] = j

    返回 next数组
```

---

**最后，完整走一遍 `"ababaca"`**

```text
下标： 0 1 2 3 4 5 6
字符： a b a b a c a
```

初始：

```text
nxt = [0, 0, 0, 0, 0, 0, 0]
j = 0
```

| `i` | 新字符 | 进入本轮时的 `j` | 本轮动作 | `nxt[i]` |
|---:|---|---:|---|---:|
| 1 | b | 0 | b 与 a 不同，保持 0 | 0 |
| 2 | a | 0 | a 与 a 相同，`j` 变成 1 | 1 |
| 3 | b | 1 | b 与 b 相同，`j` 变成 2 | 2 |
| 4 | a | 2 | a 与 a 相同，`j` 变成 3 | 3 |
| 5 | c | 3 | 接不上，`j` 从 3 退到 1，再退到 0；c 与 a 仍不同 | 0 |
| 6 | a | 0 | a 与 a 相同，`j` 变成 1 | 1 |

结果：

```text
字符： a b a b a c a
nxt：  0 0 1 2 3 0 1
```

你可以先重点看懂下面这三行之间的联系：

```python
j = nxt[j - 1]  # 原来的相同部分接不上，缩短它
j += 1          # 接得上，相同部分延长一个字符
nxt[i] = j      # 把当前找到的长度保存下来
```

尤其注意：**进入下一轮时，`j` 不重新设为 `0`。它保留上一轮的匹配长度，让我们可以接着上一轮的结果继续尝试。**
